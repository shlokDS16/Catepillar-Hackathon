# Website archetypes from the Aayush Visuals audit

These are build patterns distilled from the portfolio case studies and the live destinations inspected. They are starting points, not components to copy. For a new brief, pick the closest archetype and reshape it around the user's actual content and goals.

## 1. Personal creative portfolio — Aayush Visuals home

**Use when:** the maker's perspective, range and selected work are the product.

**Shape:** distinctive hero/identity; compact navigation; portfolio/project surface; about/proof; process; experiments; contact. Let real work provide the imagery. Make case-study entry points easy to discover.

**Craft details:** hero collage/drag interaction is optional and needs a visible instruction plus mobile/keyboard alternative. Keep the cursor ordinary unless a custom cursor has a clear interaction role. Floating support orb is a separate action, never a cursor surrogate. Project cards and CTA must work across touch and hover.

## 2. Cinematic event / cause site — Mike Tyson Invitational

**Use when:** the event has emotional stakes, ticketing/registration and multiple audiences.

**Flow:** image-led hero → why the event matters → date/venue → audience pathways → schedule/live/media → sponsor/cause story → ticket/register/donate → footer. Use an art direction budget: allocate proportions to primary event mood, impact/cause and functional details, so each visual system has a job.

**Craft details:** persistent nav and contextual bottom action can support long pages. Build menu as a fully operable portal; date copy and CTA must expire or change after the event. External ticketing/donation handoff must show provider and return/error state. Custom cursor requires ordinary focus/touch equivalent and reduced-motion support.

## 3. Operational dashboard / safety prototype — CAT Operator Assistant

**Use when:** operators need fast, context-aware actions around equipment, jobs, weather or safety.

**Flow:** role selection → authenticated/demo entry → safety/startup checklist → current machine/job overview → tasks and time estimate → safety/report/learning → machine health. Use clear status and prioritized actionable warnings.

**Craft details:** large touch targets, glove-friendly operation, offline behavior, visible units, timestamped telemetry, clear fault severity and accessibly named controls. Safety alerts require real service contracts and domain validation. Label prototype telemetry and never activate dispatch/SOS casually. Use 3D only when it clarifies inspection; provide equivalent component list/details.

## 4. Multi-party transaction platform — current LayOver site

**Use when:** a traveller, outlet/operator and venue each see different parts of a shared transaction.

**Flow:** explain fragmentation → demonstrate one basket across participants → show each participant's own ticket/settlement → explain airport/operator outcomes → audience-specific path → onboarding/integration CTA.

**Craft details:** align frontend and backend state across all roles; define one source of truth for order, payment, tickets and settlement. Simulated checkout must be visibly labeled and have no live charge. Case-study intention and current live product can diverge; separate original design rationale from current production narrative.

## 5. Editorial data report — Elevation Capital

**Use when:** a report or research finding needs a long-form, navigable story.

**Flow:** report thesis → role/category navigation → numbered insights → chart + explanatory narrative + source/method note → related insight → download/share → final role entry.

**Craft details:** charts need a clear title, units, denominator/time period, source, text summary and keyboard/screen-reader alternative. Keep report navigation visible without stealing content. Downloads should resolve to an actual accessible artifact; share should give meaningful confirmation. Never invent percentages or quote attribution.

## 6. Technical/campus event microsite — Gravitas, Riviera, Yantra, Futurepreneurs

**Use when:** a time-bound festival, competition or student event needs program, registration, team, partners and FAQ.

**Flow:** edition-specific hero → date/venue/status → program/performers or challenge → schedule/timeline → team/organizer/social proof → FAQ/contact → registration CTA.

**Craft details:** dates, registration, agenda and artist/guest content are time-sensitive; define published, open, closed, event-live and archived modes. Long kinetic marquees must not harm readability/performance. Provide direct anchor/navigation links and contact text. If a hosted page is stuck at its loader, do not infer inaccessible content.

## 7. Visual identity/poster/gallery work

**Use when:** the project is brand or campaign design rather than a web product.

**Flow:** project brief → rationale → identity system → applications/mockups → artifact gallery → credits/process.

**Craft details:** do not fabricate a login, dashboard or backend. The gallery still needs responsive layouts, accessible descriptions, image optimization, source/credit and a coherent viewer/close/keyboard pattern if lightbox is used.

## Shared craft lessons

- Start from the actual bottleneck; let that shape the hierarchy and interaction.
- Define system-level rules and the difference between primary and secondary visual moods.
- Introduce audiences/roles before asking them to interpret a complex catalogue.
- Make long pages navigable and time-sensitive content maintainable.
- Do not claim usability test outcomes or business results without evidence.
- Distinguish verified production functionality from a prototype or case-study claim.
